## 1. Optimizer Role in the MOCAP Pipeline

The MOCAP Optimizer occupies Stage 3 of the full planning pipeline:

```
QueryRequest
  → [Stage 1] Candidate Generation           (Sneha)
  → [Stage 2] Pre-execution Prediction        (Hridhika)
  → [Stage 3] MOCAP Optimizer                 (Roshini)  ← this document
       ├── 3a. Hard Constraint Filtering
       ├── 3b. Pareto-Dominance Filtering
       └── 3c. Lagrangian Ranking
  → SelectedPlan
  → [Stage 4] Execution + Adaptive/AQP        (Anaswara)
```

---

## 2. Formal Problem Statement

**Input:**
- Query *q* with budget *B* and optional deadline *D*.
- Candidate set **C** = {*c₁*, …, *cₙ*} (generated by Sneha's module).
- Predicted metrics: for each *cᵢ*, a tuple *(Ĉᵢ, L̂ᵢ)* = (estimated cost, estimated latency) produced by Hridhika's predictor.

**Objective:** Select a plan *c\** ∈ **C** such that:
1. *Ĉ(c\*)* ≤ *B*   (hard budget constraint)
2. *L̂(c\*)* ≤ *D*   (hard deadline, if specified)
3. *c\** is Pareto-optimal in (Ĉ, L̂)
4. *c\** minimises the Lagrangian objective *J(c)* (see Section 4)

> **Scientific reporting note:** Selection is *relative* to the configured model, candidate set, and constraints. No selected plan is claimed to be globally optimal.

## 3. Algorithm Pseudocode

### Algorithm 1: MOCAP Optimizer (top-level)

```
function MOCAP_SELECT(candidates C, metrics M, budget B, deadline D):

    // Stage 3a — Hard constraint filtering
    F ← FILTER_FEASIBLE(C, M, B, D)

    if F = ∅ then
        return INFEASIBLE(reason = INFEASIBILITY_REASON(C, M, B, D))

    // Stage 3b — Pareto-dominance filtering
    P ← PARETO_FRONT(F)

    if P = ∅ then
        return INFEASIBLE(reason = "Pareto frontier empty")

    // Stage 3c — Lagrangian ranking
    c* ← LAGRANGIAN_SELECT(P, B)

    return SelectedPlan(c*, budget=B, deadline=D)
```

---

### Algorithm 2: Hard Constraint Filtering

```
function FILTER_FEASIBLE(candidates C, metrics M, budget B, deadline D):

    F ← []
    rejected ← []

    for each candidate cᵢ in C do
        mᵢ ← M[cᵢ.id]

        if mᵢ = null then
            rejected.append(cᵢ, reason="no_metrics")
            continue

        cost_ok    ← (mᵢ.cost ≤ B)
        latency_ok ← (D = null) OR (mᵢ.latency ≤ D)

        if cost_ok AND latency_ok then
            F.append(cᵢ)
        else
            reason ← determine_reason(cost_ok, latency_ok)
            rejected.append(cᵢ, reason=reason)

    return F
```

**Infeasibility reason mapping:**

| cost_ok | latency_ok | reason             |
|---------|------------|--------------------|
| False   | True       | `budget_exceeded`  |
| True    | False      | `deadline_exceeded`|
| False   | False      | `both_exceeded`    |
| —       | —          | `no_metrics`       |

---

### Algorithm 3: Pareto-Dominance Filtering

```
function PARETO_FRONT(feasible_plans F):

    P ← []

    for each plan pᵢ in F do
        dominated ← false

        for each plan pⱼ in F, j ≠ i do
            if DOMINATES(pⱼ, pᵢ) then
                dominated ← true
                break

        if NOT dominated then
            P.append(pᵢ)

    return P

function DOMINATES(a, b):
    // a dominates b iff a is no worse in all objectives and strictly
    // better in at least one (with relative tolerance ε = 1e-9)
    return (a.cost ≤ b.cost + ε AND a.latency ≤ b.latency + ε)
       AND (a.cost < b.cost - ε OR a.latency < b.latency - ε)
```

**Key properties:**
- Reflexive: no plan dominates itself.
- Ties: two plans with identical *Ĉ* and *L̂* are **neither** dominated; both remain on the front (tie is broken by Lagrangian).
- Relative tolerance ε = 1e-9 prevents floating-point artefacts.

---

### Algorithm 4: Lagrangian Ranking

```
function LAGRANGIAN_SELECT(pareto_plans P, budget B):

    // Compute normalization ranges
    C_min ← min{Ĉ(p) : p ∈ P}      C_max ← max{Ĉ(p) : p ∈ P}
    L_min ← min{L̂(p) : p ∈ P}      L_max ← max{L̂(p) : p ∈ P}

    for each plan p in P do
        C_hat(p) ← NORMALIZE(Ĉ(p), C_min, C_max)
        L_hat(p) ← NORMALIZE(L̂(p), L_min, L_max)

        J(p) ← α·L_hat(p)
              + β·C_hat(p)
              + γ·A_hat(p)       // accuracy proxy (optional)
              + δ·V_hat(p)       // variance (optional)
              + λ·max(0, Ĉ(p) - B)  // violation penalty (ablation)

    return argmin_{p ∈ P} J(p)

function NORMALIZE(v, vmin, vmax):
    if vmax ≤ vmin then return 0.0
    return (v − vmin) / (vmax − vmin)
```

---

## 4. Lagrangian Objective — Equations

### 4.1 Objective Function

$$
J(p) = \alpha \hat{L}(p) + \beta \hat{C}(p) + \gamma \hat{A}(p) + \delta \hat{V}(p) + \lambda \max\!\bigl(0,\, \hat{C}(p) - B\bigr)
$$

where:

| Symbol        | Meaning                                              | Default |
|---------------|------------------------------------------------------|---------|
| $\hat{L}(p)$  | Min-max normalised predicted latency, $\in [0, 1]$   | —       |
| $\hat{C}(p)$  | Min-max normalised predicted cost, $\in [0, 1]$      | —       |
| $\hat{A}(p)$  | Accuracy proxy term (optional extension)             | 0       |
| $\hat{V}(p)$  | Variance / uncertainty term (optional extension)     | 0       |
| $\alpha$      | Latency weight                                       | 0.5     |
| $\beta$       | Cost weight                                          | 0.5     |
| $\gamma$      | Accuracy weight                                      | 0.0     |
| $\delta$      | Variance weight                                      | 0.0     |
| $\lambda$     | Violation penalty multiplier (ablation)              | 0.0     |
| $B$           | Hard budget                                          | given   |

### 4.2 Min-Max Normalisation

$$
\hat{x}(p) = \frac{x(p) - x_{\min}}{x_{\max} - x_{\min}}, \quad x_{\max} > x_{\min}
$$

When all plans have the same value ($x_{\max} = x_{\min}$), the normalised value is **0**, so the objective remains well-defined.

### 4.3 Selection Rule

$$
p^* = \arg\min_{p \in \mathcal{P}} J(p)
$$

where $\mathcal{P}$ is the Pareto front of feasible plans.

## 7. Baselines

### 7.1 Spark-Default Baseline

```
function SPARK_DEFAULT(candidates C, metrics M):
    // Simulate Catalyst: pick min-cost regardless of budget.
    return argmin_{c ∈ C} M[c].cost
```

### 7.2 Greedy Budget-Pruning Baseline

```
function GREEDY_BUDGET(candidates C, metrics M, budget B):
    F ← {c ∈ C : M[c].cost ≤ B}   // hard budget filter
    if F = ∅ then return INFEASIBLE
    return argmin_{c ∈ F} M[c].latency  // min-latency among feasible
```

## 11. Scientific Reporting Constraints

- Do **not** claim the selected plan is globally optimal; it is optimal *relative to* the configured model, candidate set, and constraints.
- Do **not** call local model-derived cost "real cloud billing".
- Do **not** present proposed/expected results as achieved results.
- Generate reported numbers from stored experiment logs, not manually edited values.
- MOCAP-R uncertainty-aware ideas remain separate from this core implementation.
